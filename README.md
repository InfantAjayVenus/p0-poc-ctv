# p0-poc

A minimal Express API for managing **subscriptions**, with structured JSON
logging that ships to Datadog.

## Features

- `GET /subscriptions` — list subscriptions (optional `?user_id=` filter)
- `GET /subscriptions/:id` — fetch a single subscription
- `POST /subscriptions` — create a subscription
- `GET /health` — liveness check
- Structured JSON logs (via [winston](https://github.com/winstonjs/winston))
  for every request, including request id, latency, and status code
- Optional direct log shipping to Datadog via
  [datadog-winston](https://github.com/itsfadnis/datadog-winston)

## Requirements

- Node.js 18+
- npm

## Setup

```bash
npm install
cp .env.example .env   # fill in values as needed
```

## Running

```bash
npm start        # node src/app.js
npm run dev       # nodemon src/app.js (auto-restart on changes)
```

The server listens on `PORT` (default `3000`).

## Subscription resource

Each subscription has:

| Field            | Type    | Notes                                   |
|------------------|---------|------------------------------------------|
| `id`             | string  | UUID, generated by the server            |
| `user_id`        | string  | required                                 |
| `transaction_id` | string  | required                                 |
| `expires_at`     | date    | ISO-8601 string, optional                |
| `activated_at`   | date    | ISO-8601 string, defaults to now         |
| `is_active`      | boolean | defaults to `true`                       |

Data is stored **in-memory** and resets on server restart.

### Examples

```bash
# Create a subscription
curl -X POST http://localhost:3000/subscriptions \
  -H "Content-Type: application/json" \
  -d '{"user_id":"u1","transaction_id":"t1","expires_at":"2026-12-31T00:00:00Z"}'

# List subscriptions
curl http://localhost:3000/subscriptions

# Filter by user
curl "http://localhost:3000/subscriptions?user_id=u1"

# Fetch one
curl http://localhost:3000/subscriptions/<id>
```

## Logging & observability

Every request gets a unique `request_id` and logs a `request.started` /
`request.completed` event (with `duration_ms` and `http.status_code`),
plus resource-specific events like `subscriptions.created`,
`subscriptions.list`, and `subscriptions.not_found`. Errors are logged
with full stack traces by the centralized error handler.

Logs are always printed to stdout as JSON, so they can be tailed by a
Datadog Agent, Docker log driver, or any log collector. To also ship logs
directly to Datadog's Logs intake API (no Agent required), set the
environment variables below.

### Datadog connection — required/available keys

Set these as environment variables (see `.env.example`):

| Variable      | Required | Description                                                                 |
|---------------|----------|-------------------------------------------------------------------------------|
| `DD_API_KEY`  | Yes*     | Your Datadog [API key](https://app.datadoghq.com/organization-settings/api-keys). Enables direct log shipping when set. If unset, logs stay on stdout only. |
| `DD_SITE`     | No       | Datadog site, e.g. `datadoghq.com` (US1, default), `datadoghq.eu`, `us3.datadoghq.com`, `us5.datadoghq.com`. |
| `DD_SERVICE`  | No       | Service name tag (default `p0-poc`).                                        |
| `DD_ENV`      | No       | Environment tag, e.g. `development`, `staging`, `production` (default: `NODE_ENV` or `development`). |
| `DD_VERSION`  | No       | App version tag (default `1.0.0`).                                          |
| `DD_HOSTNAME` | No       | Hostname tag (default: OS hostname).                                        |
| `LOG_LEVEL`   | No       | Minimum log level to emit (default `info`).                                 |

\* Only required if you want logs shipped directly from the app to Datadog.
If you're forwarding stdout via a Datadog Agent instead, `DD_API_KEY` isn't
needed here — configure the Agent itself with its own API key.

## Project structure

```
src/
  app.js                        # Express app entrypoint
  logger.js                     # Winston logger (JSON + Datadog transport)
  middleware/
    requestLogger.js            # per-request logging & request id
    errorHandler.js             # centralized error logging/response
  models/
    subscriptionStore.js        # in-memory subscription data store
  routes/
    subscriptions.js            # GET/POST /subscriptions endpoints
```
